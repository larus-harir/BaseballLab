# EraMatch 기본 자료 포함

이번 사용자 정정에 따라 **EraMatch가 제공된 과제를 기본 프로그램으로 실행**하도록 변경했습니다. 사용자에게 ZIP/CSV를 올리라고 요구하던 방식은 제거했습니다. 새 PC와 데이터 폴더가 없는 설치에서도 인터넷 없이 선수·시즌 선택 → 대결 시작으로 진행합니다.

## 실제 참조와 구현

- 새로 제공된 Python·두 CSV가 ZIP의 3개 멤버와 바이트 단위로 정확히 같음을 확인했습니다. ZIP SHA-256은 `57ab8411a07b901206b0af798d9f55a00cab79ea1d61adac492e86571b2a1058`로 기존 검토 버전과 같습니다.
- HWP 5.0 본문을 읽었습니다. 보고서 버전 4.1, 최종 수정 2026-06-16이며 목표는 KBO 시즌 집계 → 시대/표본 보정 → Log5 → 25타석 반복입니다. 보고서의 2024 김도영–1986 선동열 예시도 빈 설치에서 실행했습니다.
- 제공 자료에서 대결에 필요한 ID·이름·시즌·팀·성적·기준 리그 값만 약 1MB의 기본 자료로 컴파일했습니다. **44시즌(1982~2025), 역할별 선수-시즌 프로필 17,116개**입니다. 원본 코드·CSV·ZIP·HWP·학교·생년월일·드래프트 등의 값은 패키지에 넣지 않습니다.
- `experiments/eramatch/resources/`가 설치 패키지에 포함됩니다. `DatasetCatalog`는 유효한 기존 보관 자료를 그대로 쓰고, 보관 자료가 없으면 기본 자료를 읽습니다. 업로드·네트워크·개인 데이터 폴더 생성 없이 같은 공통 계산 엔진을 사용합니다.
- 파일 선택 폼과 ‘처음 한 번 연결’ 안내를 웹에서 제거했습니다. 과거 가져오기 API는 기존 호환·검사 목적으로 남아 있고 일반 사용자 흐름에는 없습니다.

기본 자료의 SHA·입력 파일 SHA·보고서 SHA와 제외 항목은 [매니페스트](../src/baseball_lab/experiments/eramatch/resources/manifest.json)에 기록했습니다. 런타임에는 기본 압축 자료의 고정 SHA와 카탈로그 내용 지문을 검사합니다. 원본 파일의 해시는 컴파일 때 확인한 것이며 새 PC에 원본 파일까지 있다는 뜻이 아닙니다.

## 검증

- 전체 pytest **200 passed (17.41초)**.
- 기존 원본을 실행한 재현 기준 **210조건 일치**: [기본 자료 재현 결과](results/eramatch-builtin-reproduction.json). 자료 ID도 기존과 동일합니다.
- 실제 배포 wheel을 만들고 저장소·사용자 자료가 전혀 없는 별도 폴더에서 `python -S`로 실행했습니다. **44시즌·17,116프로필·25타석 대결 성공**, 개인 파일 생성 0개. wheel 안에 기본 자료가 있고 원본 CSV/ZIP/HWP/Python은 없는지 확인했습니다.
- 실제 Chromium의 새 설치에서 네트워크를 금지한 채 EraMatch 선수 목록과 김도영(2024)–선동열(1986) 대결을 완료했습니다. 업로드 컨트롤 0개, JS 오류 0개. 기존 MLB 2023/2024·Match·모바일·재생도 함께 회귀 확인했습니다.
- 원본 재현/개선 후보를 구분하고, 원천 대조·KBO 예측 성능·시대 간 공정성이 아직 검증 전이라는 표시는 유지합니다. 보고서의 ‘운 제거·진짜 실력’ 표현을 검증된 결론으로 채택하지 않았습니다.

[업로드 없는 새 설치 화면](images/incremental/eramatch-built-in.png)

개발자용 기본 자료 빌드는 `scripts/build_eramatch_builtin.py`입니다. 일반 사용자가 원본을 준비하거나 이 스크립트를 실행할 필요는 없습니다. 기존 원본·카탈로그·연구 결과는 이동하거나 다시 쓰지 않았습니다.

실행 JSON에도 기본 자료 배포 지문과 원본 파일의 런타임 미포함 여부를 기록합니다. 기존 과제 보관 5개 파일 및 이전 보존 목록 607개 파일은 모두 해시가 유지됐습니다.
