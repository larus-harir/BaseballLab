# 점진적 재설계 독립 QA·보안 점검

이번 검토는 단일 사용자 로컬 앱의 변경 경계에 대한 확인이다. 공개 서비스 보안 인증, Windows 권한·암호화·동기화 검증이 아니다. 원본 데이터·과제·저장 연구는 수정하지 않고 임시 테스트 자료와 새 검증 산출물만 만든다.

## 검토에서 발견한 사항

| 증상 | 원인 | 수정 담당/검증 |
|---|---|---|
| 이미 연결한 과제 ZIP을 다시 연결하면 카탈로그 파일을 다시 쓸 수 있었음 | 원본 SHA 확인 뒤에도 `import_assignment`가 항상 집계를 재생성 | 데이터 담당에게 전달. 기존 카탈로그·원본 무결성을 먼저 확인하고 그대로 반환하도록 수정; 재연결 전후 바이트 검사 추가 |
| 새 2023 선수 카탈로그가 자료 관리에서 빠질 수 있음 | 기존 저장 관리 대상이 2024·과제로 고정 | 통합 담당에게 전달. 등록 시즌별 자료 관리 확장·참조 확인 요청 |
| 자동 준비가 오래 걸리면 다른 요청/사용자 조작과 충돌 가능 | 동기 처리·작업 상태·취소의 경계를 새 흐름에 연결해야 함 | 비동기 준비의 상태 조회·경쟁 변경 차단·취소·실패 검사를 추가. 취소 후 공급원 오류가 `failed`로 덮이던 경우를 발견해 취소 우선 처리로 수정 후 통과 |
| EraMatch에서 두 시즌을 빨리 바꾸면 한쪽 선수 선택이 비활성으로 남을 수 있었음 | 한쪽 검색만 다시 시작하면서 양쪽 요청 세대를 모두 무효화 | UI 담당에게 전달해 해당 검색만 무효화하도록 수정. 양쪽 연도 변경 후 실제 대결로 확인 |

## 변경 요청의 보호 경계

새 자동 준비도 기존과 같은 세션 토큰·정확한 Host/Origin 검사를 거친다. 프로젝트·시즌을 등록 목록에서 선택하며 클라이언트 URL·명령·임의 파일 경로를 다운로드 입력으로 쓰지 않는다. 빈 자료와 공급원 실패 시 성공한 선수·확률·실행을 대신 만들지 않는다. 오류의 로컬 경로·인증 문자열은 표시에서 가린다.

테스트 입력은 `MOCK_TEST_ONLY`로 표시하고 pytest 임시 폴더에만 만든다. 실제 자료를 이용한 브라우저 실행도 기존 원본은 읽기만 하고 새로운 실행 결과를 별도 폴더에 쓴다. 삭제 시험은 임시 폴더만 대상으로 한다.

## 실행 기록

`python -m pytest -q tests/test_incremental_http.py`: **4 passed (2.22초)**. 최초 실행에서는 취소 뒤 공급원 오류가 취소 상태를 덮는 테스트가 1개 실패했고, 구현 수정 후 같은 검사 전체가 통과했다. 단순 테스트 수보다 실제 작업 상태·보존 경계가 맞는지 확인했다.

`python scripts/check_incremental_browser.py`: 실제 Chromium **1366px/390px**, JavaScript 오류 **0개**. 기존 MLB 2024·새 2023 대결, KBO 과제 재사용·바이트 불변, 저장 보고서 재열기, 이전/다음/자동 재생, 기존 Match의 학습 시점·리플레이·독립 장면, 빈 검색·사용자 오류, 새 설치의 공급원 실패/재시도와 빈 과제·잘못된 ZIP을 완료했다.

최초 설치 검사는 별도 임시 루트에 카탈로그·정제 기록이 없는 상태에서 시작했다. 네트워크 전송만 **기존에 검증한 실제 공식 배포 ZIP·로스터·이용 고지의 복사 전송**으로 바꿨고, 압축 해제·실제 타석 정규화·카탈로그 생성·사용자 대결은 실제 앱을 실행했다. 원격에서 다시 다운로드한 성공으로 주장하지 않으며 합성 선수/확률은 넣지 않았다. 강제 실패 메시지는 `MOCK_TEST_ONLY`이고 운영 자료로 쓰지 않는다.

강화한 후속 `--skip-fresh` 검사는 모바일에서도 실제 백인천(1982)–원태인(2024) 대결·타석 이동을 실행했고, 데스크톱 키보드 입력과 Tab으로 3번째 타석 이동을 확인했다. 가로 넘침이 없었으며 본문/대결 버튼/결과 주석의 실제 렌더 색상 표본 대비는 각각 **10.82 / 6.28 / 4.75**였다. 이 세 색상 표본은 4.5 기준을 만족하며 전체 접근성 인증을 뜻하지 않는다.

## 미확인 범위

- Windows 사용자별 ACL·BitLocker·OneDrive·백업의 실제 구성과 동작.
- 같은 OS 계정의 악의적인 코드/메타데이터 변조와 전체 침투·퍼징 검사.
- 모든 비밀 형식·개인정보의 부재, 모든 과거 자료의 간접 의존 관계.
- 사람 대상 사용성 조사·화면읽기 접근성 인증.
