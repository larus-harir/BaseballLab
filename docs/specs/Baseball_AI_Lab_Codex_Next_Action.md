# Codex 전달 메시지 — E01 핵심 연구 우선 개발

`Baseball_AI_Lab_E01_Research_Reset.md`를 최우선으로 읽고, 기존 `PROJECT_VISION.md`와 현재 저장소의 구현을 대조해 줘.

이 프로젝트의 본질은 **AI 타자와 투수가 실제 야구 데이터로 뒷받침되는 환경에서 오직 승리를 위해 반복 경쟁할 때 어떤 전략으로 변해 가는지 관찰하고, 그 결과를 인간 야구와 비교하는 것**이야. `Baseball AI Lab`은 여러 자식 실험을 추가하는 부모 플랫폼이고, E01은 첫 번째 자식 실험이야.

현재 웹 화면, 모델, 테스트가 많이 구현된 건 알겠지만 핵심 연구는 아직 완료되지 않았어. 네 보고에 따르면 실제 자료가 없어 학습 버튼이 멈추고, 연구 보상도 경기 승리가 아니라 한 타석 출루야. **113개 테스트 통과와 실제 야구 연구 성공을 혼동하지 말아 줘.**

다음 작업은 새 UI나 추가 검증기보다는 아래 우선순위로 진행해 줘.

1. 실제 활용 가능한 데이터 제공 경로를 먼저 확인해 줘. Retrosheet 공식 플레이별 데이터와 MLB Statcast의 자료·이용 조건을 각각 검토하고, **적법하게 사용 가능한 실제 데이터를 연결하는 작동 경로**를 만들어 줘. 자동 수집 권한을 확인할 수 없으면 임의로 수집하거나 가짜 데이터로 대체하지 말고, 허용되는 방식의 재사용 가능한 연결을 제안해 줘.
2. 그 데이터로 **타자와 투수의 실제 반복 학습 → 과거 모델·고정 상대 평가 → 학습 전후 행동 변화 및 리플레이**가 웹에서 끝까지 실행되는 첫 연구 결과를 만들어 줘. 첫 단계가 타석 출루 대리목표라면 이를 정확하게 표시하고, 경기 승리 AI의 완성으로 보고하지 마.
3. 바로 이어서 **출루 대신 득점·실점과 최종 승패를 목표로 하는 최소 상황 게임**으로 확장할 계획과 근거를 세우고, 실제 데이터가 뒷받침하는 범위부터 구현해 줘. 수비·주루·번트·구종 목표 위치 등 근거가 부족한 선택지의 성공률을 임의로 만들지 마.
4. 사용자가 웹에서 **AI가 실제로 무엇을 학습했는지** 볼 수 있어야 해. 회차별 스윙/테이크, 구종 선택, 서로 다른 체크포인트의 대결, 실제 경기와 모델의 차이, 데이터 출처와 불확실성을 쉬운 한국어로 보여 줘.

기존 코드 중 맞는 부분은 유지하고 재사용해. 미래의 E02(KBO vs MLB)까지 지금 만들 필요는 없어. 더 많은 기반 코드나 완성된 것처럼 보이는 데모보다 **실제 데이터로 실행된 작은 연구 결과 하나**가 우선이야.

먼저 현재 목표와 구현의 차이를 간단히 설명한 뒤, 제일 큰 장애물부터 실제 해결을 시도해 줘. 마지막 보고는 복잡한 기술 문서 대신 `실제로 되는 것 / 아직 안 되는 것 / 실제 데이터 출처 / 학습 결과 확인 방법 / 출루와 승리 보상의 차이 / 다음 작업` 중심으로 작성해 줘. 커밋과 테스트 결과도 같이 알려줘.
