# BaseballLab 공통 플랫폼

부모는 실제 자료·규칙·경험 전이·공통 신경망·실행 및 관찰을 제공하고, Match는 연구 목표·상대·보상·전략 변화 해석을 소유합니다. 같은 저장소와 같은 서버를 사용합니다.

| 웹 경로 | 용도 | 구현 범위 |
|---|---|---|
| `/` 또는 `/lab` | 관찰 / 연구 선택 | 구현 |
| `/simulation` | 학습 없이 상황 실행 | 실제 원천 턴 / 고정 정책의 모델 상황 |
| `/lab/data` | 자료·지원 범위 안내 | Retrosheet 2023·2024, 나머지는 상태 표시 |
| `/match` | 자식 연구 선택 | A/B를 구분 |
| `/match/team` | 한 점 득점 AI 학습 | 실제 R1 경로 |
| `/match/at-bat` | 타자·투수 판단 | 기존 R0 연결, 실데이터 전제 별도 |

`simulation.scoring`은 신경망 학습기나 optimizer를 호출하지 않고 기존 경험 전이 어댑터로 관찰을 실행합니다. 실제 기록은 원문 턴과 원천 ID를 보여주며, 모델 관찰은 고정 기본/무작위 정책과 재추출 전이를 보여줍니다. 관측/생성 장면을 분류하고 재생·일시정지·턴 이동을 제공합니다.

현재는 R1의 아웃·주자·한 점 득점 상황만 독립적으로 실행합니다. 범용 9이닝·선수 라인업·교체·피로·투구 추적 시뮬레이터의 완성은 아닙니다. 부모 관찰에서는 ‘누가 AI인지’ 대신 실제 지원하는 **고정 정책**을 명시합니다.

## 책임 감사

| 구성 | 소유/상태 |
|---|---|
| `core`, `agents`, `data.lineage`, `evaluation` | 공통 규칙·정책·출처·평가 기반, 부분 구현 |
| `data.retrosheet_releases` + 기존 `r1.data/provider` | 공통 자료 어댑터. 시즌별 실제 URL·해시·정규화 옵션 등록 |
| `r1.environment` | 레거시 경로의 경험 전이/한 점 상황 어댑터. 다른 전체 경기의 구현으로 해석하지 않음 |
| `simulation` | 부모의 독립 관찰 세션. 학습 의존 없음 |
| `experiments.match.team_win` | Match-B 학습·외부 시즌 평가 |
| `experiments.match.reporting` | Match 전용 우세·개선·변화 해석과 보고서 |
| `r1.training/report` | 기존 CLI/외부 코드 호환 재노출 |
| `web` | 공통 실행 서버·부모/자식의 다른 화면 |
| 기존 synthetic 결과 모델 | 테스트 전용, 실제 연구 대체 금지 |
| Match-A의 실제 투구 연구 / Match-B 전체 승리 | 미완성 |

미래 E02의 KBO 세부 자료를 확보한 것으로 가정하지 않습니다. 시뮬레이터가 사용하는 기록·규칙과 AI가 결정 전에 보는 정보(현재 아웃·주자), 연구자가 사후에 보는 결과·정책 확률·원천 기록은 구분합니다.
