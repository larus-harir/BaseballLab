## 카탈로그 계약

- `supported_seasons(project)`: BaseballLab·Match는 개별 검토한 `[2023, 2024]`; EraMatch는 실제 연결된 카탈로그의 시즌만 반환합니다. 자료가 없으면 KBO 선수·시즌을 만들어 채우지 않습니다.
- `get(project, season=2024)`: 현재 저장된 검증 자료를 읽습니다. BaseballLab/EraMatch에는 기존 선수 카탈로그, Match에는 기존 관측 턴 자료 계약을 반환합니다. 경로를 이동하거나 기존 연구를 새 형식으로 다시 쓰지 않습니다.
- `describe(project, season=2024)`: 네트워크와 파일 쓰기 없이 준비 상태와 공통 메타데이터를 반환합니다. `provider/league/seasons/granularity/schema/units/license/acquisition_method/acquired_at/version/sha256/row_count/missingness/entity_ids/known_biases/allowed_uses/capabilities`를 포함합니다. `verified_at`은 실제 전체 해시 검사 시점이며, 뒤의 파일 지문 조회 시각 `cache_checked_at`과 다릅니다. 이전 수집 시각을 새 검증 시각으로 바꾸지 않습니다.
- `ensure(project, season=2024, progress=None)`: 유효한 보관 자료는 무쓰기·무다운로드 재사용합니다. 누락 MLB 자료만 등록된 공식 제공자로 준비하고, EraMatch는 등록된 비공개 위치의 원본 ZIP을 재사용합니다. 원본이 없을 때만 최초 한 번의 연결을 안내합니다. 진행 콜백의 중지 예외를 삼키지 않습니다.
- `list_sources()`: 각 제공원을 독립적으로 검사합니다. 하나가 손상되면 그 항목만 실패 상태로 표시하고 다른 유효한 제공원을 숨기지 않습니다. 자동 복구·리그/연도 대체·자료 덮어쓰기는 하지 않습니다.

Match 메타데이터 읽기는 큰 기존 JSON의 manifest 앞부분과 고정 원본 ZIP/CSV를 검사합니다. 실제 실행에서는 기존 `r1.data.load`가 정제 턴 전체와 계보를 다시 검사합니다. 공통 등록 API가 기존 Match의 공식 버전 핀 검사를 우회하지 않도록 원본 검사를 먼저 수행합니다.

KBO에서는 서로 다른 팀 행을 합산하는 339그룹과 모호한 중복 4그룹이 기존 방식대로 유지됩니다. 타자 9,525 프로필은 개선 후보의 사건 구성을 제공하고, 투수 7,591 프로필 중 4,242개는 피2루타/피3루타 결측이어서 개선 후보를 계산하지 않습니다. 이 결측을 0으로 채우거나 현재 KBO로 바꿔 실행하지 않습니다. 과제 재현 가능 여부와 개선 후보 가능 여부는 별도 표시합니다.
