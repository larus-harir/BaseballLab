## 공통 데이터·실행 계약

- `DatasetCatalog.describe/get/ensure`는 기존 저장소 위에서 데이터 준비·출처·해상도·이용조건·원본 해시·결측·식별자·지원 기능을 제공합니다. 조회는 네트워크/쓰기 없이, 준비만 누락된 등록 자료를 요청합니다.
- BaseballLab/EraMatch는 같은 서비스와 `simulation.contracts`를 사용합니다. 기록 분모·사건 합·전체 확률·실행 개수를 검증하고 `engine_version/model_version/dataset_ids/assumptions/prediction_scope/random_seed/simulation_count/coverage/uncertainty/model_limitations`를 저장합니다.
- 기존 관찰은 `contextual_trace`, 선수 대결은 `independent_pa`입니다. 장면 기록에 없는 사건 확률을 만들어 공통 형식에 억지로 끼우지 않습니다. 기존 JSON을 덮어쓰지 않고 새 실행에만 계약을 덧붙입니다.
- Match CLI와 독립 시즌 평가도 공통 카탈로그로 원본을 요청합니다. 원본 ZIP/CSV 고정 해시를 검사한 뒤 기존 정제 턴 전수검사를 그대로 거치며 학습·보상·가중치·과거 평가 수치는 바꾸지 않았습니다.
- `/api/catalog`는 공통 자료 상태, `/api/knowledge`는 지표 정의·분모·단위·원천·실제 모델 사용 여부를 제공합니다. 지표 사전 15개가 모두 AI 입력으로 사용된다는 뜻이 아닙니다.

## Match·EraMatch와 다음 연구

Match의 현재 R1은 세 아웃 전 한 점 득점/저지입니다. 기존 경쟁 학습·과거 상대·체크포인트·2023 외부 평가를 보존했습니다. 이번에는 데이터 요청 경계를 공유했고 실제 투구/9이닝 학습으로 바꾸지 않았습니다. 통계 예측 점수가 좋아도 새 행동의 인과 결과가 검증됐다고 연결하지 않습니다.

다음 작은 전술 연구로 정상 승부/고의볼넷을 같은 상대·출발 상태에서 통제 비교하는 [관측·행동·보상·자료·평가 계약](match/next-tactical-study.md)을 선정했습니다. 현대 3시즌·장기간 역사 변화 비교는 Match의 로드맵이고, 세 번째 시즌은 검토 전 지원으로 표시하지 않습니다. EraMatch는 과제의 역대 선수 대결을 계속 제공합니다.
