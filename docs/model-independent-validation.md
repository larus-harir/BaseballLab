# 고정 설정의 다른 시즌 검사와 계산 검토 · 2026-11-11

이번 검사는 기존 모델을 새 이름으로 갈아 끼우는 작업이 아니다. 기존
`matchup.models`의 이항/다항 Log5와 평균 회귀를 그대로 호출하고, 같은 보류
타석에서 계산 방식과 표본 조건에 따른 예측 오차를 비교했다. 원본 자료,
기존 카탈로그, 연구 결과·가중치, 이전 검증 JSON을 덮어쓰지 않았다.

## 달라진 검증

| 이전의 빈틈 | 이번 수정 | 확인한 근거 |
|---|---|---|
| MLB 2024 한 시즌의 점수만 있음 | 2023 앞 기간의 선수 기록으로 마지막 기간을 별도 검사 | 실제 2023년 39,198타석·515경기 |
| 합계 점수만으로 작은 표본을 설명하기 어려움 | 알려진 양측 선수/새 선수, 작은/큰 앞 기간 표본을 분리 | 그룹별 N·로그손실·Brier·교정 |
| 모델 간 점수 차이의 변동 범위가 없음 | 같은 경기를 짝지어 200회 재추출 | 경기 단위 percentile 구간, 재현 번호 고정 |
| 지표 이름이 있다는 사실과 실제 모델 입력을 혼동 | 15개 지표의 정의·분모·단위·원천·가용성·사용 여부를 분리 | 공유 `data.knowledge.get_knowledge()` |

## 검사 설계

- 2024 검증 구간에서 고른 가상 표본 강도 **300**을 2023에도 고정했다.
  2023의 중간 구간이나 마지막 구간으로 강도를 다시 고르지 않았다.
- 2023년 7월 15일 전 **103,668타석**에서만 선수·리그 비율을 만들었다.
  중간 **41,238타석**은 분리해 두고 모델 선택에 사용하지 않았다. 8월 25일
  이후 **39,198타석**을 모든 비교 모델이 동일하게 예측했다.
- 경기 ID의 시작 날짜 대신 원본 CSV의 실제 날짜를 사용했다. 중단 후 재개
  경기는 마지막 타석이 관측된 날짜로 경기 전체를 배정해 기간이 겹치지 않는다.
- 모르는 선수 쪽은 앞 기간의 리그 비율을 사용했다. 나중에 관측한 선수의
  기록으로 앞 기간 프로필을 보충하지 않았다.
- 이 검사는 **독립적인 다른 시즌의 회고적 검사**다. 2024에서 선택한 설정을
  2023에 적용했으므로 미래 예측 실험이라고 부르지 않는다. 2023은 기존 Match
  연구에서도 사용했으므로 과학적으로 사전 등록된 미공개 표본이라는 주장도 하지 않는다.

## 실제 결과

작을수록 좋은 점수이며 모든 행은 같은 39,198타석이다.

| 계산 방식 | 로그손실 | Brier |
|---|---:|---:|
| 선수 효과 없이 앞 기간 리그 빈도 | 1.507705 | 0.712416 |
| 타자만 표본 보정 | 1.498172 | 0.708738 |
| 공유 다항 Log5 | 1.495130 | 0.707356 |
| 사건별 이항 Log5 후 정규화한 비교 후보 | 1.495153 | 0.707369 |

마지막 행은 과제 원본의 순서 추첨과 다르다. 각 사건을 one-versus-rest로
이항 결합한 뒤 전체 합으로 나누는 **탐색용 비교 후보**다. 분포 합을 1로
만들었다는 사실만으로 통계학적으로 선호되는 모형이 되는 것은 아니다.
이번 검사로 기본 모델을 자동 교체하지 않았다.

다항 모델의 리그 빈도 대비 로그손실 차이는 **−0.012575**이며, 같은 경기를
짝지어 다시 뽑은 200회의 중앙 95% 구간은 **[−0.014309, −0.011154]**였다.
다항과 이항 후 정규화 후보의 차이는 **−0.0000225**로 작다. 그 조건부 구간은
**[−0.0000369, −0.0000077]**이며, 이 작은 차이를 리그·시대·전술 전체에서의
우수성으로 확대하지 않는다. 전체 수치는
[2023 검사 JSON](results/incremental-2023-independent-validation.json)에 있다.

예측은 전체 타석에 계산됐지만, 양측 선수가 앞 기간에 모두 있었던 비율은
**80.8%**다. 새 선수 쪽을 리그 평균으로 대체한 타석 **7,520개**, 한쪽이라도
앞 기간 표본이 100 미만인 타석 **17,511개**를 따로 표시했다. 100은 보고를
위한 고정 분류 기준이며 선수의 실제 기량 안정화 시점이라고 주장하지 않는다.

| 다항 Log5의 검사 그룹 | 타석 수 | 로그손실 |
|---|---:|---:|
| 양측 선수 앞 기간 기록 있음 | 31,678 | 1.495831 |
| 한쪽 이상 새 선수 | 7,520 | 1.492179 |
| 한쪽 이상 앞 기간 100 미만 | 17,511 | 1.497965 |
| 양측 모두 앞 기간 100 이상 | 21,687 | 1.492842 |

이 그룹들은 타석 구성이 다르다. 새 선수 그룹의 점수가 낮다는 이유로
기록이 없는 편이 좋다고 해석하지 않는다. 안타 확률 구간별 예상/관측 수와
전체 8개 사건의 교정 집계는 같은 JSON에 있다.

경기 단위 구간은 관측한 경기들을 다시 뽑는 근사다. 모델을 재학습하지 않으며
선수 공유·일정의 상관관계, 모형 선택, 결측, 자료 오염, 전술의 인과적 불확실성
전체를 포함하지 않는다. 여러 지표의 동시 비교에 대한 오류율 보정도 하지 않았다.

## 기존 수치 보존

- 실제 MLB 2024의 동일한 마지막 **36,306타석**을 다시 계산했다. 기존 리그,
  타자, 다항 모델의 로그손실·Brier는 이전 JSON과 **모든 수치 차이 0**이었다.
  기존 원본과 artifact는 읽기만 했다. 이 결과는 별도의
  `statistical-same-season-regression-v1` 형식이며 독립 시즌 검사라고 표시하지 않는다.
  [재계산·원본 지문](results/incremental-2024-regression.json)
- 기존 과제 검증 스크립트를 실행해 실제 조합 40개와 테스트 전용 극단 2개,
  각 난수 5개에서 **210조건의 25타석 사건 수와 표시 확률**이 원본과 일치했다.
  이것은 원본 `simulate()` 이후의 계산·추첨 재현이며, 원본 CSV의 정확도나
  이름 검색의 동명이인 처리, 시대 보정의 공정성을 검증한 것은 아니다.
  [이번 재현 기록](results/incremental-assignment-reproduction.json)
- 새 검사의 합성 입력은 `MOCK_TEST_ONLY` 단위 테스트에서만 쓰며 실제
  카탈로그나 결과로 복사하지 않았다. 검사 모듈은 카탈로그를 준비하거나
  기존 선수 기록을 재생성하지 않는다.

## 계산과 근거 검토

다항 모델은 `bᵢ × pᵢ / lᵢ`를 전체 사건 가중치 합으로 나눈다. 이항 특수
경우와 리그 평균을 한쪽에 넣었을 때의 성질은 기존 공통 엔진 테스트로
확인한다. 원본 재현은 BABIP 강제 평균, 고정 보정 상수, SF 결측 0, 순서대로
추첨하는 규칙까지 드러내고 유지한다. 표시한 이항 사건의 합과 실제 순서
분기의 사건 확률은 다를 수 있다. 개선 모델은 사건 전체를 겹치지 않게 나누고
필수 사건의 결측을 임의의 0 확률로 채우지 않는다.

SABR의 다항 Log5 설명과 MLB의 지표 정의를 대조했다. 지식 사전의 참조
14개 URL은 실제 제목과 정의 본문을 확인했다. MLB는 없는 경로도 빈 틀을
HTTP 200으로 반환할 수 있어 응답 코드만으로 확인하지 않았다.
[짧은 근거 식별·원천 지문](results/incremental-knowledge-references.json)

지식 사전은 AVG/OBP/SLG/OPS/BABIP/K%/BB%/K9/BB9/FIP/wOBA/wRC+/WAR/DIPS/Log5를
담는다. WAR·wRC+는 단일한 보편 산식을 지어내지 않았고, wOBA의 시즌별 가중치나
FIP의 정렬 상수를 임의로 제공하지 않았다. 지표가 등록됐다는 사실은 AI가
그 지표를 모두 배웠거나 실제 모델 입력으로 사용한다는 뜻이 아니다.

## 직접 실행과 한계

```bash
python -m pytest -q tests/test_incremental_statistics.py
python scripts/validate_assignment.py
```

독립 검사 함수는 실제 자료를 준비한 뒤 연구자 코드에서 호출한다. 대상과
설정 기준이 같은 시즌이면 자료에 접근하기 전에 거부한다. 같은 시즌의 수치
회귀 검사는 `validate_rows()`와 기존 artifact 비교로 분리한다.

```python
from pathlib import Path
from baseball_lab.matchup.validation import validate_external
report = validate_external(Path('.'), year=2023, reference_year=2024)
```

새 통계 단위 테스트 **7개 통과**. 전체 테스트·브라우저 검사는 통합 보고를
따른다. 새 시즌의 점수 개선은 실제 선수·구장·팀·상대 선택의 인과 효과,
KBO나 시대 간 공정성, AI 전략 변경의 효과 또는 9이닝 승패의 검증이 아니다.

검증 함수는 공통 카탈로그에서 이미 보관한 공식 원본만 읽습니다. 원본이 없으면 준비 안내로 중단하며 검증 조회에서 네트워크 다운로드를 시작하지 않습니다. 이를 별도 테스트로 확인했습니다.
