# BaseballLab-Match

부모 BaseballLab 위에서 경쟁하는 AI의 전략 변화를 연구하는 첫 자식(E01)입니다. 웹의 `/match`에서 연구 종류를 구분합니다.

- **Match-A `/match/at-bat`**: 개별 타자·투수 판단. 기존 R0 스윙/기다리기·구종 경로는 보존하되 실제 투구 자료 연결과 반사실 모델의 검증이 필요합니다. 학습 완료로 표시하지 않습니다.
- **Match-B `/match/team`**: 팀 측 전술. 현재 실행 범위는 **한 점 득점/차단 R1**입니다. 전체 경기 승리 AI의 기초 실험이며 9이닝 게임은 아닙니다.

## 결과를 읽는 순서

결과 첫 화면은 ‘현재 맞대결 우세 → 같은 상대에 대한 학습 전후 개선 → 처음부터 지금까지 → 선택 변화’ 순서입니다. 사용자가 전체 대결표를 읽어 결론을 조립하지 않아도 됩니다. 플레이·상세 비교·자료와 한계는 별도 탭에 보존합니다. 원본 기록이나 정책 가중치를 변경하지 않고 요약을 계산합니다.

우세는 현재 두 정책이 같은 조건에서 직접 대결한 득점률로 판단합니다. 95% 표본 구간이 50%를 벗어나고 최소 두 반복에서 방향이 같을 때 표시합니다. 차이가 작거나 방향이 다르면 보류합니다. 이 판정은 설정한 시작 상태·평가 환경의 **성공 빈도**이며 역할의 본질적 난이도나 실제 야구의 일반적 실력 우열을 식별한 것은 아닙니다.

성장은 각 역할이 **같은 고정 상대**를 상대했을 때 학습 전후 성공률로 비교합니다. 공격 득점률과 다른 대결의 수비 차단률을 빼서 누가 강하다고 결론 내리지 않습니다. 여러 seed의 방향 일치와 보수적인 구간 차이를 함께 확인하며, paired 검정/다중 시점 검정을 했다고 표시하지 않습니다. 구간에는 모델·자료·선택 편향 불확실성이 빠져 있습니다.

추이 그래프는 저장 시점끼리의 대각 교차대결을 사용합니다. 모든 점은 같은 최종 확인 기간 환경에서 사후 평가한 값이며, 검사 기간의 중간 기록과 다른 기간의 최종 수치를 섞지 않습니다. 선택 확률은 같은 지원 상황의 평균이고, 선택 변화만으로 개선의 원인을 설명하지 않습니다.

## 코드 경계와 호환

학습기는 `experiments/match/team_win/training.py`, 연구 결과 해석·화면은 `experiments/match/reporting/`에 있습니다. `r1.training`과 `r1.report`는 기존 호출을 유지하는 호환 경로입니다. 기존 E01-R1 연구 JSON·체크포인트의 스키마·행동·파라미터를 바꾸지 않았습니다. 웹은 예전 research.json을 읽어 새 결과 화면을 만들며 원본 HTML/JSON을 덮어쓰지 않습니다.

부모는 출처·신경망·HTTP 실행·독립 관찰을 제공합니다. 레거시 `r1.environment`와 `r1.data/provider`는 현재 경험 전이·자료 어댑터 경로로 재사용하며 대규모 이동을 하지 않았습니다. 공통 핵심 모듈이 Match의 학습기를 참조하지 않습니다.

## 독립 시즌 평가

2023·2024년 공식 배포를 각각 해시로 등록했습니다. 날짜 입력으로 한 시즌씩 학습할 수 있습니다. 여러 시즌을 무조건 섞어 학습하는 기능이나 선수·구장 효과의 인과 통제는 아직 없습니다.

저장 정책을 다른 시즌에서 재학습 없이 평가하려면 다음을 실행합니다. `경로`는 실제 연구 결과의 research.json으로 바꾸세요.

```powershell
python -m baseball_lab.experiments.match.team_win.external --research "경로/research.json" --year 2023
```

원래 학습의 지원 행동과 가중치를 고정하고, 새로운 시즌으로만 결과 환경을 만듭니다. 별도 `external-2023.json`을 저장하며 원래 연구 파일은 수정하지 않습니다. 웹 보고서의 **자료와 한계 → 학습에 쓰지 않은 시즌에서 확인**에 표시됩니다.
