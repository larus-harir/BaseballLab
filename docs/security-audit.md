# 자료 보호 점검 · 2026-11-05

단일 사용자 PC의 로컬 앱을 점검했습니다. **포괄적인 보안 인증이 아닙니다.** 현실적인 야구 모델인지와 자료를 안전하게 다루는지는 다른 검사입니다. 실제 원본·저장 모델을 삭제하지 않았고, 삭제 검증은 임시 `MOCK_TEST_ONLY` 자료에서만 실행했습니다.

## 유지한 기본 방어

로컬 `127.0.0.1` 바인딩, 정확한 Host·Origin 검사, 변경 요청의 세션 토큰, 고정 CLI 인수·shell 미사용, 단일 작업 제한, 32MB 업로드 한도, 결과 경로 제한, 실제/가상/테스트 구분, 원본 계보와 Retrosheet 고지를 유지합니다. 개인 PC의 신뢰된 사용자 전제이며 공개 서비스의 로그인·사용자 격리는 제공하지 않습니다.

의존 관계는 저장된 연구의 시즌 정보와 외부 평가 기록에서 확인한 연결입니다. 가져온 임의 파일의 모든 간접 의존성을 자동 발견한 것으로 주장하지 않습니다. 파일 변경 시각은 실제 마지막 사용 시각과 다르다고 화면에 명시합니다. 해시 검사 상태는 현재 프로세스에서만 기억하며 파일 지문이 달라지면 재검사 상태가 됩니다.

## Git 검사와 실제 전송 범위

`python scripts/audit_repository.py`는 추적 중인 사적 자료 경로와 Git 이력의 알려진 GitHub/AWS 키·개인키 패턴을 검사합니다. 발견 값 자체는 출력하지 않습니다. 최초 점검에서 추적 파일 124개, 역사적 blob 225개 중 해당 발견은 0개였습니다. 최종 점검의 범위·결과는 [검증 기록](ux-validation.md)에 남깁니다. 모든 개인정보/비밀의 부재를 증명하는 검사는 아닙니다.

공식 자료를 준비할 때 Retrosheet로 HTTPS 요청합니다. 앱에 사용자 CSV·가중치를 외부 서비스로 업로드하는 경로는 없습니다. Git에는 원본/가중치가 아닌 승인된 집계와 코드·화면만 배포합니다. 브라우저에서 외부 고지 링크를 누르거나 OS 동기화/백업 프로그램이 실행되는 것은 별도 동작입니다.

## 아직 확인하지 않은 것

- Windows 사용자별 ACL, BitLocker/디스크 암호화, OneDrive 등 실제 동기화 설정과 백업 안전성. 경로 이름 감지는 참고 표시이며 탐지 보장이 아닙니다.
- 침투 테스트·모든 인코딩/압축/파서 변형에 대한 퍼징, 모든 비밀 형식 탐지, 의존 패키지 취약점 전수 감사, 보안 제품 인증.
- 같은 PC의 다른 프로세스·사용자는 신뢰한다는 로컬 앱 전제입니다. 루프백 포트의 세션 토큰은 OS 계정 로그인이나 사용자별 인증을 대신하지 않습니다.
- 같은 OS 계정이 악의적으로 연구 파일·코드를 바꾸는 상황에 대한 방어, 저장 파일 전자서명·자동 암호화·복구/암호화 백업.
- 실제 화면읽기 프로그램을 사용하는 사람 대상 접근성 시험. SVG 상태 설명·live 영역·키보드는 구현/브라우저 검사했지만 전문 검증은 아닙니다.
- 공개 인터넷/LAN 서비스의 인증·사용자 격리·HTTPS·속도 제한. 현재 기본으로 제공하지 않습니다.

실제 원본을 삭제하지 않고 동일 출처 보관본·기존 체크포인트를 사용했습니다. 선택 편향·선수/점수/카운트 생략·반사실 모델 가정은 이 보안 조치로 해결되지 않습니다.

## 2026-11-09 통계 프로그램 확장

기존 로컬/Host/Origin/토큰/경로/삭제 방어를 유지했습니다. 새 POST도 같은 경계 안에서만 실행합니다. 선수 입력은 고정 카탈로그 ID이며 임의 URL·파일 경로나 명령을 받지 않습니다. 과제 ZIP은 최대 8MiB 및 검토한 원본 해시·정확한 멤버를 검사하고 앱에서 원본 Python을 실행하지 않습니다. 잘못된 ZIP은 원본/실행 결과를 만들지 않습니다. 별도 원본 검증 스크립트만 명시적 실행 시 검토한 클래스의 simulate를 호출하며 import/main은 호출하지 않습니다.

카탈로그 경로·멤버/하위 파일의 링크를 거부하고 원본 파일 해시와 카탈로그 내용 지문을 검사합니다. 캐시는 파일 크기·변경 시각 지문이 달라지면 재검사합니다. 같은 계정의 악의적 파일/메타데이터 동시 변조에 대한 방어는 보장하지 않습니다. 저장 결과의 JSON은 HTML 스크립트 경계를 빠져나가지 않도록 이스케이프하고 가변 문자는 escape 또는 textContent로 출력합니다.

선수 카탈로그도 기존 두 단계 삭제·확인·변경 감지에 연결했습니다. KBO 원본은 비공개 자료로 분류하고 통계 실행의 참조 수를 표시합니다. 자료 삭제 시 저장 결과의 확률·모델·원본 해시는 남지만 원본에서 재계산하려면 자료를 다시 준비해야 합니다. 알려진 직접 참조를 표시하는 범위이며 간접 의존성 전수 추적은 아닙니다.

원본/체크포인트·2023 외부 평가 106개 파일의 해시 보존, 빈 자료/잘못된 ZIP/스크립트 삽입/권한/등록 ID/경로/캐시 변경/결측 검사를 수행했습니다. 상세 결과는 [이번 검증](three-project-validation.md)을 따릅니다. 공개 서비스 보안 인증·암호화·Windows ACL 검증으로 확대 해석하지 않습니다.

## 2026-11-11 보존형 개선

자동 준비를 기존 Host/Origin/토큰·단일 변경 작업 경계에 통합하고, GET 상태를 막지 않는 작업·협력적 취소·실패/재시도를 검사했습니다. 입력 프로젝트/시즌은 등록 목록에서만 선택하며 임의 URL/경로/명령을 받지 않습니다. 같은 ZIP 재연결과 캐시 조회는 무쓰기이고, Match 공통 조회도 공식 버전 핀 검사 뒤 정제 턴을 검증합니다. 2023 카탈로그도 용량·검사·참조·삭제 확인에 포함했습니다. [독립 QA 결과](incremental-security-review.md)와 [최종 통합 게이트](incremental-redesign-validation.md)를 따릅니다. 기존 607개 보관 파일은 해시 일치로 보존을 확인했으며 새로운 암호화·Windows 권한 인증을 주장하지 않습니다.
