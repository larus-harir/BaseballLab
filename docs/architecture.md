# 부모 플랫폼과 자식 실험

E01의 run.py는 설정을 읽어 `RuleSet + LeagueProfile + OutcomeModel`을 공통 Engine에 주입하고 `MatchSpec`별 평가를 실행합니다. 리그 이름에 따른 엔진 분기는 없습니다. 프로파일 변경만으로 결과 확률이 자동 보정되는 것은 아닙니다. 새 calibration_id에는 실제 대응 모델을 주입해야 하며 불일치하면 실패합니다.

규칙 엔진은 ball/strike/foul/in-play 사건을 카운트와 타석 종료로 바꿉니다. OutcomeModel은 합법 투구·스윙 행동을 확률 사건으로 바꿉니다. 확률은 엔진 밖에서 관리하므로 향후 데이터 보정 모델을 교체할 수 있습니다. 현재 투구의 zone은 실제 좌표가 아닌 이산 목표이며, take의 판정에도 합성 오차가 있습니다. 투구·스윙은 같은 사전 공개 관측으로 결정되며 타자는 현재 투구 정보를 받지 않습니다.

`Policy.act(observation, legal_actions, rng)`는 합법 행동 하나를 반환합니다. 타자·투수·결과 RNG를 분리했습니다. 동일 설정과 Python/코드 버전에서 재현되며, 서로 다른 정책의 난수 사용량이 상대 정책 스트림을 바꾸지 않습니다. 같은 seed도 정책에 따라 타석 길이가 달라지므로 투구별 공통 난수 짝짓기나 공정성 보장을 뜻하지는 않습니다.

현재 관측은 카운트만 포함하는 `count-v1`, 행동은 `discrete-pitch-swing-v1`입니다. `PolicyMetadata`에는 훈련 리그·규칙·보정·데이터 버전·알고리즘·seed·commit을 기록하며 명시적 호환성 검사에서 불일치 스키마를 거부합니다. M1 기준선은 체크포인트 로딩을 하지 않습니다. 향후 로더는 평가 전에 이 검사를 반드시 호출해야 합니다. 프로파일의 스키마/규칙/보정 호환성은 Engine 생성 시 검사합니다.

새 자식 실험은 자체 설정과 가설을 가지고 공통 평가 코드를 호출합니다. 새 데이터 어댑터는 출처·단위·결측·이용 조건을 검증해 결과 모델에 전달합니다. 현재 데이터 어댑터, 학습 루프, 동적 플러그인 시스템은 구현하지 않았습니다.

타석마다 카운트를 초기화하며 주자·이닝·득점은 없습니다. 과도한 연속 파울은 safety limit 예외로 보고하며 임의 삼진이나 승패로 처리하지 않습니다. 후속 전체 경기 단계에서 주자·수비·피로와 현실 능력 제약을 검증하고 경기 승패 보상을 도입합니다.
