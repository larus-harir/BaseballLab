# BaseballLab · 야구 연구실

실제 기록으로 선수를 맞붙이고, AI가 전략을 바꾸는 과정을 살펴보는 서비스입니다.

| 경험 | 할 수 있는 일 |
|---|---|
| **선수 가상 대결 (EraMatch)** `/eramatch` | MLB/KBO/NPB 선택 → 시즌·선수·타석 수 → 결과·재생·계산 원리 |
| **AI 전략 연구 (Match)** `/match` | 학습 시작 → 선택 변화·상대 비교·장면 관찰 |

BaseballLab은 브랜드와 공통 통계 엔진입니다. 기존 `/baseball` 경로와 `project=baseball` 저장 결과는 MLB 대결로 계속 열립니다. 수집 자료가 있으면 기본 화면에서 MLB 2000~2025, KBO 1982~2026, NPB 2025를 선택합니다. 이전 과제·검증 모형은 개발자 정보의 **사용할 기록**에서 선택할 수 있고, 새 설치에서도 앱에 포함된 약 5.4MB의 리그별 시즌 집계로 대결합니다. MLB·KBO·NPB 대결에 원본 CSV 다운로드는 필요하지 않습니다. 원본과 저장 결과는 보존합니다.

현재 기준: [디자인 우선 지시](docs/specs/BaseballLab_Design_First_Codex_Directive.md).

## 시작하기

Python 3.11 이상을 설치하고 저장소 폴더에서 실행하세요.

```powershell
git pull origin main
python -m pip install -e ".[learning]"
python scripts/quickstart.py --open
```

서버가 이미 켜져 있으면 Ctrl+C로 종료한 뒤 다시 여세요.

- **선수 가상 대결 → 대결하기:** 같은 화면에서 MLB·KBO·NPB를 선택합니다. 결과는 핵심 수치·분포·타석 순서로 볼 수 있습니다. **계산 원리** 탭에서 선택한 선수의 기록과 보정·Log5·추첨 과정을 실제 숫자로 확인합니다. **개발자 정보**에는 설정·원천·재현·검증 근거가 있습니다.
- **AI 전략 연구 → 투구·타격 전략 학습:** MLB·KBO·NPB와 연도를 고른 뒤 **AI 학습 시작**을 누릅니다. 기본값은 2010년 이후 확보한 36개 경기 환경과 이전 시즌 참고 기록입니다. 공격·투구 정책 각 하나가 양쪽 역할의 경험과 경기 승패로 학습하며, 결과에서 자주 쓴 행동·같은 상황의 선호 변화·투구와 타구 구역을 확인합니다. GPU 없이 실행할 수 있습니다.

기본 선수 대결은 수집 기록을 바로 사용합니다. 두 선수와 리그 기준에 있는 홈런·장타·사구는 각각 구분하고, 누락된 안타 종류만 묶습니다. KBO·NPB 투수의 피2루타·피3루타가 없더라도 확보한 홈런은 별도로 계산합니다. MLB 선수는 앱에 포함한 공식 ID·이름 명부로 표시·검색합니다. 계산 원리·예상과 이번 결과·타석 재생·같은 대결 재현에서도 실제 사용 사건을 유지합니다. 구분 가능한 기록이 없는 사건은 0개로 표시해 만들어내지 않습니다.

결과의 **실제 기록 살펴보기**에서 MLB 각 수집 시즌의 타구·투구 결과 코드, KBO 선수 계수와 2024년까지의 팀 주루·수비 표, NPB 원문 구속 예시를 볼 수 있습니다. NPB 좌표는 단위·기준 검증 전이므로 원문만 보여 줍니다. 팀 기록을 선수의 인과 효과나 AI의 가상 결과로 대입하지 않습니다. **야구 장면 살펴보기**에도 수집한 MLB 시즌 선택을 연결했습니다. **자료 관리**는 수집 원본·비공식 CSV·표준 집계·학습 전이를 표시하고 검증할 수 있습니다.

기존 **MLB 기간 선택 연구·이닝 연구**는 등록된 공식 시즌 ZIP을 메모리에서 읽고, SHA-256을 검사한 뒤 기존 정제·학습 엔진으로 처리합니다. 원본 ZIP/CSV와 정제 데이터셋을 디스크에 저장하지 않습니다. 이미 보관한 ZIP이 있으면 검증해 읽습니다. 여러 시즌을 고르면 통신량·RAM 사용량·처리 시간이 늘어납니다. 통신 없이 학습하는 기능은 아닙니다. 원본이 없으면 재실행 때 다시 읽으며, 결과·가중치·로그는 계속 저장됩니다. 다른 시즌이나 허구 선수로 대체하지 않습니다. 결과는 이 PC에 저장되고 각 프로젝트에서 다시 열 수 있습니다.

Match의 **AI 학습 시작**은 통합 야구 전략 학습을 실행합니다. 이닝 득점 연구는 새 학습 메뉴에서 제거했으며 기존 실행 결과와 CLI는 보존합니다. 첫 화면은 공격·투구 선택의 변화와 학습 기록을 바탕으로 한 해설을 보여주고, 자세한 비율·결과 수치는 펼쳐 확인합니다.

아래의 이닝 혼합 설명은 보존된 이전 실험에 해당합니다. 이 실험은 리그별 타석 빈도로 보정하는 방식이며, 현재 통합 투구 학습과 다릅니다.

혼합 환경의 주자·아웃 전이는 MLB 관측 기록을 공통으로 쓴다는 **검증 전 운반 가정**입니다. KBO는 검사 시작 전에 완료된 시즌, NPB는 검사 시작일보다 앞선 정규시즌 관측 경기만 빈도 보정에 사용합니다. 시즌 합계를 가짜 KBO·NPB 경기 전이로 바꾸거나 서로 다른 리그의 수준이 같다고 인증하지 않습니다. 자세한 데이터 흐름은 [리그 혼합 학습 규칙](docs/league-data-contract.md#리그-환경-혼합-학습)을 확인하세요.

선수 대결 결과에는 **예상 개수와 이번 개수 그래프**, 장타·삼진 해석, 결과별 타석 찾기가 있습니다. MLB의 아웃·희생타·실책 세분은 실제 기록 구성에 따른 참고 추정입니다. KBO 시즌 합계로 구분할 수 없는 결과는 아웃으로 단정하지 않습니다.

일반 **대결 시작 / 다시 대결**은 매번 새 표본을 추첨합니다. 확률은 같은 조건에서 유지됩니다. **같은 대결 재현**은 당시 번호와 계산 조건을 사용해 타석 순서까지 복원하며, 저장 이력은 별도 실행으로 남습니다. 직접 번호를 지정하려면 세부 설정의 **번호를 고정해 재현하기**를 선택합니다. 저장 HTML은 웹의 결과 목록에서 열어 재실행할 수 있습니다.

Match 날짜는 선택한 시즌의 실제 기록 범위 안에서 고릅니다. 범위 초과·종료일 역전·3일 미만의 학습 기간은 시작 전에 안내하고 차단합니다. 화면 이동과 상태 확인은 자료를 읽거나 계산하는 동안에도 사용할 수 있습니다.

MLB 대결 결과의 **선수의 실제 타구·투구 기록 살펴보기**에서는 시즌의 타구 종류·첫 처리 수비 위치·투구 결과 순서를 봅니다. 이는 가상 대결의 궤적 예측과 구분합니다. 속도·발사각·구종·존 좌표는 현재 원천에 없습니다. [확인한 필드와 2025 추가 원본 수집](docs/data-contact-feasibility.md).

## Match 연구 결과는 어떻게 읽나요?

실제 저장 연구에서 **1,500번 중 704번(46.9%) 득점**, 나머지 796번은 차단됐습니다. **이 비율만으로 수비 AI가 더 잘한다고 판정하지 않습니다.** 공격과 수비가 맡은 과제가 비대칭이고 24개 시작 상황도 실제 경기 빈도와 다르기 때문입니다. 이전 버전의 50% 기준 ‘우세’ 해석은 철회했습니다.

같은 방식으로만 플레이하는 비교 상대에게는 수비 차단률이 **28.9% → 52.1%**로 좋아졌고, 공격의 개선은 확인되지 않았습니다. 숫자는 유지하고 해석을 바로잡았습니다.

새 결과 화면은 **바뀐 선택 / 같은 상대에 대한 바뀐 성과 / 아직 말할 수 없는 것**을 보여줍니다. 상황·학습 시점을 움직이며 선택 확률과 실제 누적 횟수를 구분하고, 같은 출발 상황의 저장 장면을 나란히 볼 수 있습니다. 이전 실행도 웹에서 새 화면으로 열립니다. 기존 JSON·저장 모델·HTML 원문은 덮어쓰지 않습니다.

## 자료는 어디에 있나요?

실제 수집 범위는 MLB **2000~2025년 4,925,133플레이**, KBO 공개 배포본 **1982~2026 선수 18,180행**과 팀·수비·주루 CSV, NPB 비공식 **CSV 98개·674,754행**입니다. NPB 2025 정규시즌으로 확인된 858경기는 1,002개 선수·역할·시즌 기록으로 집계했습니다. 중복 제공자를 합쳐 표본을 부풀리지 않습니다. 원본 범위·관측 단위·이용 조건은 [수집 현황](docs/data-collection-status.md)을 확인하세요.

```powershell
# 공식 원천에서 내려받기 (기존 검증된 자료는 재사용)
python scripts/collect_league_seasons.py --leagues MLB --start-year 2000 --end-year 2025
python scripts/collect_community_data.py
python scripts/collect_npb_community.py --prepare
# 확보한 전체 기간 / 리그별 최근 5시즌 선택
python scripts/prepare_league_data.py
python scripts/prepare_league_data.py --last-seasons 5
```

EraMatch의 **수집한 리그·시대의 공통 기록으로 비교하기**에서 MLB·KBO·비공식 NPB 자료를 같은 사건 정의로 비교합니다. Match 학습 화면에는 확보한 **전체 기간·최근 5시즌·개별 시즌** 선택이 나타납니다. 원본과 기존 집계의 검증값을 확인해 재사용하며, 기존 신경망 학습과 결과 화면으로 이어집니다. 시즌 합계로 구종 선택이나 투구 궤적을 만들지 않습니다. 결측값·최소 요건·보정 가정·출처별 결정은 [공통 자료 규칙](docs/league-data-contract.md)을 따릅니다. 공식 NPB 수집본의 제한과 비공식 배포본의 라이선스 선언은 별도로 취급합니다. 게시자의 라이선스는 upstream 권리·정확성의 독립 검증을 뜻하지 않습니다.

EraMatch 기본 자료는 앱 패키지에 포함된 대결용 시즌 집계입니다. 생년월일·학교·드래프트 항목과 원본 CSV/ZIP/코드/HWP는 포함하지 않습니다. [원본 대조·기본 자료 검증](docs/eramatch-default-data.md).

기존 통계 선수 카탈로그·과제 원본은 `data/local/catalog/`, 공식 경기 원본은 `data/local/retrosheet/`, 별도 사용자 투구 자료는 `data/local/statcast/`, 실행 결과는 `outputs/`에 보관합니다. **자료와 신뢰성** 화면에서 용량·분류·연결된 연구·원본 해시를 확인할 수 있습니다. 삭제는 대상과 재현성 영향을 확인하고 다시 동의한 경우에만 진행하며 자동 삭제하지 않습니다.

웹은 `127.0.0.1` 로컬 전용입니다. 앱 자체 암호화는 없으며 Windows 권한·백업·동기화의 안전을 확인했다고 주장하지 않습니다. 새 POSIX 저장 자료의 접근 권한을 제한하고, 공개 화면·로그의 로컬 경로와 인증정보를 가립니다. 원본과 가중치를 Git에 배포하지 않습니다.

기존 MLB 기간 선택·이닝 연구의 학습 설정은 **MLB 시즌**을 고르면 해당 시즌 전체를 사용합니다. 날짜 입력은 선택 사항인 세부 설정으로 접어 두었습니다. 학습 버튼 위의 자료 안내에서 실제 보정에 쓰는 KBO 시즌·NPB 관측 범위를 확인하세요. 예를 들어 MLB 2024를 사용하면 KBO는 2023 완료 시즌이며, 2024 앞 구간에 NPB 관측이 없으면 그 사실을 표시합니다. 모든 리그를 같은 연도로 맞춘다는 뜻이 아닙니다.

선수 가상 대결은 타자·투수 시즌을 독립적으로 선택합니다. 확장 수집 자료뿐 아니라 이전 MLB 2023·2024 카탈로그에서도 교차 시즌 대결을 지원합니다. 이 경우 동일 시즌 예측 검사 결과를 교차 시즌 성능으로 표시하지 않습니다. 로컬에 NPB 원본이 없어도 앱에 포함된 2025 정규시즌 집계를 사용합니다. 다른 리그를 대신 사용하지 않으며, NPB만 준비된 경우에도 기존 MLB 자료는 유지합니다.


일반 화면은 대용량 원본을 자동 저장하지 않습니다. 약 5.4MB의 앱 포함 집계는 대결용이며, 이를 실제 경기 전이로 간주하지 않습니다. NPB 혼합 학습에는 정규시즌으로 확인된 경기의 일자별 타석 계수를 사용해 검사 시작일 이후 기록을 제외합니다. 기존 원본·결과는 자동 삭제하지 않습니다. 개발자용 수집 스크립트는 별도 보존합니다.

기존 폴더와 휴지통은 우선 보존하고, 다른 이름으로 코드를 다시 받습니다. PowerShell:

## 이전 전체 경기 연구 (보존된 결과)

이 절은 보존된 `Match-whole-game-v1` 결과의 설명입니다. 현재 메인 화면은 아래의 **매 공의 행동 학습**을 사용합니다. 이전 연구도 9이닝과 연장·끝내기를 이어 진행했습니다. 한 팀은 공격·수비 신경망을 함께 사용하며, 경기 끝의 승리 +1 / 패배 -1만으로 학습합니다. 득점·번트·도루 자체의 보너스나 정답 전략은 주지 않습니다. 상대는 고정 상대와 과거 저장 정책을 섞고, 학습 후 같은 고정 상대에게 홈·원정을 번갈아 독립 추첨으로 평가합니다. 결과에는 승률·추첨 불확실성·같은 상황의 선택 확률 변화·실제 행동 수·경기 장면이 나옵니다.

이전 전체 경기 연구의 지원 행동은 일반 타격, 관측된 초구 스윙/지켜보기, 번트, 도루, 승부/고의볼넷입니다. 앞 구간에 30건·중간 점검에 10건 이상 있는 상황만 추가 행동을 엽니다. 최종 평가 자료로 행동을 고르지 않습니다. 없는 결과는 임의 확률로 채우지 않습니다. 구종·코스·타순 편성·개별 선수 교체·수비 배치·피로 학습은 아직 지원하지 않습니다. 관측 행동의 결과를 새 상황에 사용하는 가정은 인과 효과를 입증하지 않으며, 1~8회 자료를 경기 후반으로 옮기는 가정도 검증 전입니다. 연장은 무사 2루로 시작하며, 18회 동점·한 이닝 200회 안전 한도는 임의 승패 대신 오류로 종료합니다.

기존 **한 이닝 득점 연구**의 결과와 CLI는 보존합니다. `/match/team?study=half_inning`은 현재 통합 학습 화면을 엽니다. 이전 체크포인트·결과·원본과 숨겨진 레거시 실행 경로는 삭제하지 않습니다. 이전 연구의 스키마는 `Match-whole-game-v1`입니다.


이전 `Match-whole-game-v1` 결과의 **A팀은 학습한 AI**, **B팀은 고정 비교 상대**입니다. 현재 메인은 아래의 통합 정책 학습으로 이어집니다. ‘한눈에 보기’는 평가 전체 승패와 저장한 한 경기의 점수판을 구분하고, 각 팀의 타격·주루 담당과 투구 담당이 선택한 행동·득점·허용 득점·아웃을 보여줍니다. ‘경기 따라보기’에서 이닝·주자·공수 행동과 다음 득점 장면을 이동하며, ‘학습 변화·근거’에서 A팀의 공격·수비 선택 변화를 따로 확인합니다. 기존 결과도 화면만 새로 읽으며 원본 JSON·모델·학습 보상은 변경하지 않습니다. 이전 결과에 새 구종·코스 정보를 소급 생성하지 않습니다.


## 메인 학습: 투구·타격 선택과 성장

기본 학습은 `Match-pitch-decision-game-v8`입니다. **2010년 이후 확보한 모든 리그 자료를 하나의 경로로 사용**합니다. 코스가 없다는 이유로 시즌 전체를 제외하지 않습니다. 한 공격 정책과 한 투구 정책이 양쪽 연습 역할의 경기 승패로 함께 배우며, 결과는 통합 AI의 플레이 선택과 변화입니다.

| 자료 | 실제 사용하는 범위 | 사용 방법 |
|---|---|---|
| MLB 경기 기록 | 2010~2026 | 카운트·타격·주루와 관측된 구종·코스·구속 |
| KBO 경기 기록 | 2016~2026 | 구종·타격·주루, 2023~2026은 시즌당 720경기의 추가 추적 자료 |
| NPB 경기 기록 | 2019~2026 | 타격·주루와 확인된 구종·화면 코스 |
| 이전 시즌 합계 | MLB 2010~2025, KBO 2010~2026, NPB 2015~2025 | 해당 경기 환경보다 이전에 완료된 시즌의 특징만 정책 입력으로 사용 |

전체 **36개 환경·15,053,562개 투구**를 계수·중간 점검·최종 검사에 나눠 사용합니다. 이전 완료 시즌 합계는 투구 수에 더하지 않습니다. KBO2010~2015·NPB2015~2018 기록도 과거 시즌 입력으로 사용하며, 없는 개별 경기 상태를 만들어내지 않습니다. NPB2010~2014는 현재 관측 배포본을 확보하지 못했습니다. UI에 리그별 경기 기록·시즌 참고 기록 범위를 함께 표시합니다.

- **하나의 학습:** 추적 교재/비추적 교재를 사용자가 따로 고르지 않습니다. 기본 전체 기간에서 세 리그를 함께 배웁니다. 리그별 연습 기회를 고르게 배정하고 리그 안에서 연도를 순환해, 반복당 51경기면 전 환경을 한 번 이상 경험합니다.
- **빠진 항목 처리:** 코스 없는 기록도 경기·타격·주루 학습에 사용합니다. 입력에는 필드 유무를 구분하고, 세부 구종·코스·구속대 선택은 해당 관측과 레퍼토리가 있을 때 엽니다. 좌표를 다른 리그 평균으로 채우지 않습니다.
- **결과:** 사용 행동 요약, 구종·코스 분포, 같은 상황의 선택 확률 변화와 실제 경험 범위를 봅니다. 코스 히트맵은 추적값이 있는 부분만 그리며 **그 분모와 전체 투구 수를 함께 표시**합니다. 세부 기록이 많은 일부 시즌을 전체 야구로 확대 해석하지 않습니다.
- **자료 보존:** 새 통합 계수 약 3.52MB만 앱에 추가합니다. 일반 실행에서 원본 다운로드는 필요 없습니다. 기존 데이터·결과·가중치·교재는 삭제하거나 덮어쓰지 않으며 이전 보고서는 이전 의미로 엽니다.

구종·코스는 관측 결과를 조건으로 한 추정이며 실제 조준·제구의 인과 효과를 입증하지 않습니다. 타격 방향도 기록된 접촉 방향의 목표 모델이며 실제 타자의 의도는 아닙니다. 드문 셀은 같은 리그·연도 안에서 축소 추정하고 주루는 실제 인원 보존 규칙을 검사합니다. 날짜 앞 60%로 추정하고 다음 20%로 모형을 고르며 마지막 20%로 예측을 검사합니다. 경기 승패 외의 전략 보너스나 권장 행동 비율을 정답으로 주지 않습니다.

출처·범위·정규화 정책은 [자료 규칙](docs/league-data-contract.md#전체-현대-야구-통합-학습-v6), 실제 추가 수집 실적은 [수집 현황](docs/data-collection-status.md#전체-현대-야구-통합-학습-v6)에 있습니다.

### 학습 갱신과 실행 시간

기본 정책은 경기 마지막 승패를 대상으로 하는 **가치 기준선 + PPO**로 갱신합니다. 득점·안타 보너스나 권장 행동 비율은 주지 않습니다. 기존처럼 긴 경기의 행동을 한 번만 크게 묶어 갱신하던 방식에 비해, 같은 경험을 작은 묶음으로 제한적으로 반복 사용합니다. 정책·가치 함수의 가중치와 최적화 상태는 양쪽 연습 역할에서 동기화합니다. 이전 REINFORCE 결과·체크포인트는 보존합니다.

- 동일한 기록 지문·모형 코드에 대한 검사 결과를 약 9KB의 검증 통계로 재사용합니다. 자료·모형이 달라지면 다시 계산하고, 파일 지문이 틀리면 거부합니다. 독립 검사나 데이터 필드를 빼는 최적화가 아닙니다.
- 행동 마스크와 합법 선택의 중복 계산을 줄이고 JSON의 모든 필드를 간결한 형식으로 저장합니다. 데이터·환경·3회 재현·학습 보상·경기 규칙은 유지합니다.
- 요약은 **전체 실행에서 합산한 실제 행동**을 보여줍니다. 방향별 스윙은 전체 스윙에 포함하고 방향 분포는 따로 표시합니다. 학습 변화는 같은 상황의 전후 확률이며 타격 판단·방향과 구종·코스를 나눠 봅니다. 비슷한 확률을 학습 성공이나 실패로 단정하지 않습니다.
- 새 체크포인트에는 행동의 순서를 함께 저장합니다. 과정마다 달라지던 집합 순서로 다른 행동에 가중치가 연결되는 일을 막습니다.

v7 개발 환경의 고정 조건(102경기·1개 재현 번호·전체 36환경·단일 BLAS 스레드) 순차 측정에서 기존 **26.58초 → 9.26초**였습니다. 모형·독립 예측 지표와 사용 환경이 같은지 대조했습니다. PC별 속도는 다르며 장기 전략 수렴의 검증과 별개입니다. 상세 근거는 [학습 검증](docs/league-data-contract.md#승패-정책-갱신-v7)에 있습니다.

### 보존된 MLB 기간 선택 연구 (v1·v2)

기존 설정은 **사용할 학습 기록 → 기존 MLB 기간 선택 연구**에서 계속 실행합니다. 이전 결과·가중치·원본은 덮어쓰지 않습니다. 아래 설명은 이 경로에 해당합니다.

기존 MLB 경로는 `pitch_game`의 v2 방식이며, 이 경로의 새 실행은 `Match-pitch-decision-game-v2`로 저장합니다. 이전 v1 결과도 그대로 읽습니다. 이전의 일반 타석/초구 접근/도루 결과 묶음 선택 연구는 삭제하지 않고 별도 스키마로 보존합니다. 공격 AI는 매 투구에 스윙·지켜보기·번트 또는 지켜보며 2·3루 도루를 시도하는 선택을 배웁니다. 수비 AI는 현재 투수로 투구·고의볼넷·실제 투수 교체를 선택합니다. A팀과 B팀의 공격·수비 신경망 네 개가 모두 마지막 승패만 보상으로 학습하며 홈·원정을 번갈아 맡습니다. 고정 B팀을 실제 인간 전략으로 취급하지 않습니다.

실제 Retrosheet 투구 순서가 완결되고 해석 가능한 타석만 사용합니다. 카운트·선택·실제 투수 ID를 입력으로 하는 수치 확률 모델을 앞 구간에서 학습하고, 나중 날짜의 투구에서 예측 오차와 단순 빈도 기준의 오차를 공개합니다. AI가 과거 타석 ID나 안타·홈런 결과를 행동으로 고르는 경로는 없습니다. 경기 중 과거 원문 행을 결과로 뽑지 않으며, 학습한 투구 결과 분포와 진루 전이 확률로 카운트·아웃·주자·점수를 이어갑니다. 진루 표본이 없는 상태는 임의로 채우지 않고 중단합니다.

모든 해석 가능한 학습 앞 구간 투수 자료가 공통 모델을 학습시키고, 앞 구간에서 많이 관측한 실제 투수 세 명을 양 팀의 대칭 실험 명단으로 사용합니다. 실제 구단 명단의 재현은 아닙니다. 투수 재등판은 금지하고 최소 세 타자 또는 이닝 종료 후 교체합니다. 세계 모델·진루 계수·정책 체크포인트·자료 지문·코드 지문·예측 오차를 새 출력에 저장합니다.

현재 자료에 없는 구종·코스·구속·타구 방향은 생성하지 않습니다. 관측 행동을 조건으로 학습한 모델은 행동 변경의 인과 효과를 증명하지 않으며, 완성된 물리 야구 시뮬레이터나 자유로운 야구 전반의 지능이라고 주장하지 않습니다. 실제 경기의 미래 투구 예측 검사와, 학습한 모델 안의 가상 경기 승률을 구분합니다. 기존 한 이닝 연구·과거 전체 경기 연구·체크포인트·결과는 그대로 남습니다.

투구 결과 모델은 학습 구간의 카운트·스윙 여부별 관측 빈도를 출발점으로 삼고 투수별 차이를 추가 학습합니다. 중간 점검의 Brier 오차로 추가 학습 단계와 빈도 모델 중 하나를 선택하며, 마지막 날짜 구간은 선택에 사용하지 않습니다. 추가 학습이 더 나쁘면 빈도 모델을 사용하고, 그 경우 투수 교체의 결과 확률 차이가 반영되지 않음을 알립니다. 투구 순서에서 제외한 이유·표본 수와 별도로 재사용한 실제 진루 기록 수를 결과에 남깁니다.

결과 상단에는 두 팀의 현재 우세 여부와 가상 평가 경기의 표본 불확실성을 표시합니다. 각 팀을 **학습 시작 때 저장한 상대 AI**와 다시 겨뤄 전후 변화를 비교하며, 같은 상황의 스윙·고의볼넷 선택 확률도 제공합니다. 저장 상대는 인간 야구의 기준 전략이 아닙니다. 투수 교체·고의볼넷에는 타격 결정을 생성하지 않습니다. 최종 경기 평가는 진행 점검과 다른 난수 묶음을 사용합니다. 예전 결과에 없는 전후 비교는 만들어 표시하지 않습니다.

연결이 잠시 끊기면 동일한 공식 주소로 최대 세 번 연결합니다. 접근 거절·인증서 오류·자료 해시 불일치는 우회하지 않습니다. 끝내 실패하면 결과 버튼 대신 **같은 설정으로 학습 재시도**를 표시하며, 새 실행 폴더에서 다시 시작합니다. 서버를 재시작해도 이전 실패 기록의 설정으로 재시도할 수 있습니다. 설정이 없는 옛 버전 기록은 **설정하고 다시 학습**으로 이동하며 진단 페이지를 성적으로 표시하지 않습니다.

번트는 [Retrosheet 공식 코드 정의](https://www.retrosheet.org/eventfile.htm)의 L(번트 파울)·M(번트 헛스윙)·O(번트 파울팁)와 실제 번트 인플레이 표기를 사용합니다. 2스트라이크 후 번트 파울은 삼진이며, 번트 진루를 일반 스윙의 진루로 대체하지 않습니다. 도루는 투구와 함께 기록된 단독 SB2/SB3/CS2/CS3 장면에서 볼카운트와 성공·실패를 함께 추정합니다. 타석 종료와 결합하지 않은 0~2볼·0~1스트라이크 장면을 대상으로 하며, 더블스틸·견제·실책·폭투와 혼합된 사건은 아직 모델링하지 않습니다. 해당 카운트·주자 상태에 학습 구간 관측 10건 이상인 행동을 열고, 표본 수와 이후 날짜의 예측 검사 범위를 저장합니다. 10건은 실험용 최소 지원 기준이며 통계적 안정성이나 전략의 인과 효과를 보장하지 않습니다. 결과의 저장 경기에서 가능했던 행동과 실제 선택 확률, 번트·도루의 전후 선택 변화를 확인할 수 있습니다.

### 통합 학습 결과 v8

결과는 전체 실행의 행동을 합산하고 같은 기준 상황의 선택 확률을 평균합니다. 리그·재현·카운트를 고르는 메뉴 대신 통합 요약, 코스 전후 비교, 12개 카운트 표를 제공합니다. 구종·코스·구속대의 승패 신호를 공유하면서 개별 조합 출력을 유지합니다. 선택 변화에는 실제 사용량·결과와 갱신 전 승패 신호를 연결하며, 관측된 땅볼 비율을 AI의 생각이나 구종의 인과 효과로 쓰지 않습니다. 독립 학습을 한 정책의 연속 학습으로 합친 것은 아니며 기존 원본과 체크포인트는 보존합니다.

학습 결과의 첫 화면은 타격·구종·코스 선택을 바꾼 경험을 문장으로 정리합니다. 승패 신호가 불리하거나 기록이 없으면 그 한계를 그대로 설명하며, 구종·높이 조합의 실제 결과는 펼쳐 확인합니다. 진행률은 모든 반복 학습의 경기 수를 합산하고, 메뉴는 통합 학습과 학습 결과로 간소화했습니다. 원본 실행 기록과 이전 연구 결과는 보존됩니다.

### 결과를 한눈에 보기

기존 학습 결과 상단의 **한눈에 보기**를 누르면 같은 실행 기록으로 만든 별도 요약 보고서를 엽니다. 핵심 변화, 공격·투구 요약, 같은 기준으로 비교한 전후 코스 선호, 실행 간 변화 방향을 보여줍니다. **자세히**를 누르면 기존 상세 화면의 해당 탭으로 돌아갑니다. 기존 결과 화면·기록은 유지합니다.

통합 학습 v7/v8의 저장 결과는 서버에서 원본을 고치지 않고 요약을 열 수 있습니다. 새 실행에는 `report.html`과 `overview.html`을 함께 저장해 파일로도 연결됩니다. 중간 저장·전후 비교가 없는 기록은 구분하며 이미지·PDF 내보내기 기능은 포함하지 않습니다.

### 화면 구성 정리

홈에서 선수 대결 또는 AI 학습으로 바로 이동합니다. 통합 학습 화면은 리그·연도·연습량과 결과 확인에 집중하며, 사용하지 않는 날짜·업로드·이닝 연구의 화면 분기를 제거했습니다. 기존 엔진·CLI/API·저장 결과는 보존합니다. 선수 대결의 타석 재생은 **타석별 기록**에서 펼치고, 관찰의 진행 방식은 가상 장면에서만 설정합니다. 자료 관리는 실제 확보 범위를 표시하며 기존 삭제 검토·동의 절차를 유지합니다.

### 제품·디자인 통합 검토

기획·디자인·야구/자료 신뢰성·QA 검토를 반영했습니다. 홈, 선수 대결, 다른 리그 비교, 학습, 자료 관리와 보고서에 공통 디자인을 적용하고 메뉴·모바일·키보드 흐름을 통일했습니다. 다른 리그 비교는 입력을 바꾸면 이전 결과를 접으며, 계산 중 입력 잠금과 응답 구분으로 과거 결과가 현재 설정에 섞이지 않게 했습니다. 핵심 결과·예상/이번 막대·타석 탐색은 같은 실행 기록을 사용합니다.

해설은 무투구 고의볼넷과 실제 투구의 분모를 구분하고, 구종 안의 순위·기준 상황·높이 확인 표본을 명시합니다. 공동 경기 규칙과 방향 타격의 인과성 한계는 결과 근거에 남깁니다. 원본·모든 시즌·가중치·이전 결과는 보존하며 공통 스타일은 저장 HTML에도 포함됩니다.
